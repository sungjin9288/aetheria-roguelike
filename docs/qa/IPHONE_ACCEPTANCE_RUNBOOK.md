# iPhone 실기기 수용 런북

제품 통합 수용(원장 §67)과 Wave 66(§68) 뒤의 다음 단계다. 클라우드 세션에는 Xcode와 실기기가 없다. 그래서 이 단계는 **소유자 Mac + 소유자 iPhone**에서 진행한다. 설치 · 실행 · 저장 복원 경로는 2026-09-14 재설치 기록(`docs/evidence/qa/latest-iphone-install-20260914.md`)과 같다.

- 대상: `main` 최신 커밋. 받은 SHA를 결과에 적는다.
- 번들: QA 번들 `com.aetheria.roguelike.freshqa`. 기존 세이브를 유지하므로 삭제 · 초기화하지 않는다.
- 운영 번들 `com.aetheria.roguelike`에는 설치하지 않는다.

## 1. 빌드 · 설치 · 실행(소유자 Mac)

```sh
git checkout main && git pull
npm ci
npm run mobile:doctor              # 서명 · 프로비저닝 상태 점검. App Store 배포 서명은 이 단계에 필요 없다
npm run cap:sync                   # 프로덕션 빌드 + iOS · Android 동기화
npm run ios:archive:fresh-qa       # QA 번들로 서명된 아카이브
npm run ios:device:fresh-qa:smoke  # 설치 + 실행 + 프로세스 확인
```

- 기기 식별자 기본값은 스크립트에 적힌 페어링 기기다. 다른 기기면 `xcrun devicectl list devices`로 식별자를 찾아 `AETHERIA_IOS_DEVICE_ID=<식별자>`를 앞에 붙인다.
- 기기가 잠겨 있으면 설치 · 실행이 막힌다. 화면을 켠 채로 둔다.
- "신뢰하지 않는 개발자"가 뜨면 기기의 설정 > 일반 > VPN 및 기기 관리에서 개발자 앱을 신뢰한다. 그 뒤 `npm run ios:device:fresh-qa:launch-smoke`로 실행만 다시 한다.
- 스크립트는 설치 · 실행 영수증(JSON)을 안에서 검증한 뒤 지운다. 결과에는 명령마다 종료 코드와 `[ios-device-smoke]` 출력 줄을 붙인다.
- 스크립트는 앱이 화면 앞에 떴는지 증명하지 못한다(스크립트도 그렇게 출력한다). 화면은 기기 또는 iPhone 미러링으로 직접 본다. 9/14 기록도 미러링으로 확인했다.

## 3. 판정 경계

- 이 런북은 **iPhone 한 대의 화면 · 수명 주기 수용**이다. Android 에뮬레이터 결과와 Android 실기기 수용은 따로 다룬다. 소유자에게 Android 실기기는 없다.
- 클라우드 저장 동기화는 인증 지연 · 오프라인 안내가 보이면 통과로 기록하지 않는다(9/14 기록과 같은 기준).
- 서명 · 업로드 · 스토어 입력은 제품 수용 뒤 별도 릴리스 단계다. 결제는 출시 범위 밖이다(§68.2).
- 결과는 `docs/evidence/qa/iphone-acceptance-<날짜>/`에 영수증(JSON) · 스크린숏 · 항목별 판정으로 남긴다. 항목 6이 실패하면 글꼴 수정 작업으로 이어진다.
