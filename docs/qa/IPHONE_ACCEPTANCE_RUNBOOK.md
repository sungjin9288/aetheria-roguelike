# iPhone 실기기 수용 런북

통합 수용 7차(원장 §149)와 Wave 136(§150)까지 머지된 화면을 소유자 iPhone에서 확인하는 절차다. 클라우드 세션에는 Xcode와 실기기가 없다. 그래서 이 단계는 **소유자 Mac + 소유자 iPhone**에서 진행한다. 설치 · 실행 · 저장 복원 경로는 2026-09-14 재설치 기록(`docs/evidence/qa/latest-iphone-install-20260914.md`)과 같다.

**기기에서 다시 보는 이유:** 저장소의 화면 계약(e2e)은 Linux Chromium의 iPhone 12 에뮬레이션(375 · 390 · 430px)에서 잰다. iPhone은 WebKit으로 그리고, 본문 글꼴이 시스템 글꼴 스택(`--aether-readable-font`)이라 Apple 시스템 글꼴로 그린다. 글자 폭이 다르므로 줄바꿈 · 잘림 경계는 기기에서 다시 본다. 안전 영역 · 터치 · 백그라운드 복귀 · 강제 종료는 에뮬레이션이 재지 못한다.

- 대상: `main` 최신 커밋. 받은 SHA와 기기 모델 · iOS 버전을 결과에 적는다.
- 번들: QA 번들 `com.aetheria.roguelike.freshqa`. 기존 세이브를 유지하므로 삭제 · 초기화하지 않는다.
- 운영 번들 `com.aetheria.roguelike`에는 설치하지 않는다.

## 1. 빌드 · 설치 · 실행(소유자 Mac)

```sh
git checkout main && git pull
npm ci
npm run mobile:doctor              # 서명 · 프로비저닝 상태 점검. App Store 배포 서명은 이 단계에 필요 없다
npm run cap:sync                   # 프로덕션 빌드 + iOS · Android 동기화
npm run ios:archive:fresh-qa       # QA 번들로 서명된 아카이브
npm run ios:device:fresh-qa:smoke  # 설치 + 실행 + 프로세스 확인
```

- 기기 식별자 기본값은 스크립트에 적힌 페어링 기기다. 다른 기기면 `xcrun devicectl list devices`로 식별자를 찾아 `AETHERIA_IOS_DEVICE_ID=<식별자>`를 앞에 붙인다.
- 기기가 잠겨 있으면 설치 · 실행이 막힌다. 화면을 켠 채로 둔다.
- "신뢰하지 않는 개발자"가 뜨면 기기의 설정 > 일반 > VPN 및 기기 관리에서 개발자 앱을 신뢰한다. 그 뒤 `npm run ios:device:fresh-qa:launch-smoke`로 실행만 다시 한다.
- 스크립트는 설치 · 실행 영수증(JSON)을 안에서 검증한 뒤 지운다. 결과에는 명령마다 종료 코드와 `[ios-device-smoke]` 출력 줄을 붙인다.
- 스크립트는 앱이 화면 앞에 떴는지 증명하지 못한다(스크립트도 그렇게 출력한다). 화면은 기기 또는 iPhone 미러링으로 직접 본다. 9/14 기록도 미러링으로 확인했다.

## 2. 기기에서 확인할 것

각 항목에 통과 / 실패 / 해당 없음과 스크린숏을 남긴다. 실패하면 화면 · 조작 순서 · 기대와 실제를 적는다.

**글자 크기 기준:** 화면의 글자는 어디서나 11px 이상이다(Wave 133, 원장 §146). 기기에서는 기준 글자와 비교한다 — 상태 표시줄 첫 줄의 '레벨 N'이 11px이다. 그보다 눈에 띄게 작은 글자가 있으면 실패다.

| # | 확인 | 통과 기준 | 근거 |
|---|---|---|---|
| 1 | 앱 실행 · 저장 복원 | 로딩 → 이전 세이브가 복원된다(레벨 · 위치 · 골드가 업데이트 전과 같다) | 9/14 기록과 같은 경로 |
| 2 | 귀환 브리핑 | 마지막 플레이 6시간 뒤에 열면 뜬다. 칸 이름 · 수치가 '레벨 N'보다 작지 않고 잘리지 않는다. 6시간이 안 됐으면 해당 없음 | §146.1 |
| 3 | 상태 표시줄(마을 · 필드) | 첫 줄은 이름 · 직업 · 레벨 · 골드다. 폭이 모자라면 직업만 줄어든다. 이름은 일곱 글자 안팎까지 그대로 보인다(상한 6.5rem — 더 길면 끝이 줄임표다). 지역 이름은 둘째 줄 맨 앞에 줄임표 없이 전부 보인다. 그 줄의 칩(보스 접근 · 연속 처치 · 상태이상)이 많으면 다음 줄로 넘어가도 통과다 | §146.2 |
| 4 | 마을 원정 준비 | 마을에는 안내 줄이 없다. '원정 준비'에 목적지 · 목표 두 칸, 준비 칩, 주 단추 하나가 있다. 주 단추가 지금 상황과 맞다 — 진행 중인 임무가 있으면 '○○(으)로 출발', 없으면 '임무 고르기', 가방이 거의 차면 '가방 정리하기' | §150 |
| 5 | 상점(마을) | 장비 줄의 구매 판단(추천 · 대표 변화 '공격력 −N' · 세트 기여), 가격, 구매 단추가 '레벨 N'보다 작지 않다. '상세 보기'와 판매 탭에서도 같다. 판매 줄의 효과 요약은 줄임표 대신 줄을 넘긴다 | §146.1 |

### 2.5 마지막에, 원할 때만 — 사망 화면

죽으면 여정이 처음부터다(Wave 108 — 무엇이 남는지는 사망 화면의 "다음 여정에 남는 것" 줄이 말한다). 일부러 죽지 않는다. 이 QA 세이브의 여정을 잃어도 될 때, 또는 확인 중에 실제로 죽었을 때만 본다.

## 3. 판정 경계

- 이 런북은 **iPhone 한 대의 화면 · 수명 주기 수용**이다. Android 에뮬레이터 결과와 Android 실기기 수용은 따로 다룬다. 소유자에게 Android 실기기는 없다.
- 종장 화면(진 엔딩 · 계승 · 회차 규칙 카드)은 이 세이브가 그 단계에 있을 때만 본다. 세 폭 화면은 e2e(`true-ending-new-game-plus` · `ascension-journey-design` · `screen-english-words`)가 잰다.
- 네이티브 시작 경로(`SceneDelegate`)는 2026-09-22 scene QA(`docs/qa/IOS_SCENE_LIFECYCLE_QA.md`) 뒤로 바뀌지 않았다. 이 런북은 웹 화면과 앱 수명 주기만 본다. 네이티브 코드를 바꾸면 scene QA를 다시 돌린다. 항목 15의 근거인 iOS 27 캡처는 커밋 `604603af`에 있다.
- 클라우드 저장 동기화는 인증 지연 · 오프라인 안내가 보이면 통과로 기록하지 않는다(9/14 기록과 같은 기준).
- 서명 · 업로드 · 스토어 입력은 제품 수용 뒤 별도 릴리스 단계다. 결제는 출시 범위 밖이다(§68.2).
- 결과는 `docs/evidence/qa/iphone-acceptance-<날짜>/`에 영수증(JSON) · 스크린숏 · 항목별 판정으로 남긴다.
  - 항목 9가 실패하면 글꼴 수정 작업으로 이어진다.
  - 글자 크기 · 잘림 · 누락 항목(2 · 3 · 5 · 12 ~ 15 · 21)이 실패하면 화면 · 폭(디스플레이 확대 여부) · iOS 버전을 함께 적는다. e2e 에뮬레이션에서는 통과한 화면이므로, 다음 작업은 기기 글꼴 폭이 원인인지부터 가른다.
