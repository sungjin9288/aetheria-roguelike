1. **정지점은 이미 멈춘 자리에 둔다.** 전투 · 승리 직후에 새 화면을 끼우지 않는다(Wave 127 · D1).
2. **잃는 것 옆에 남는 것 하나.** 죽음이 매번 이야기 한 줄을 남긴다(Hades 원리, 문구는 우리 것).

## 1. B1 장 결산

### 1.1 장 정의 — 세 후보 비교

| 후보 | 장점 | 결정적 결함 |
|---|---|---|
| (a) 본편 16장(`STORY_CHAPTERS`) | 서사가 이미 있다 | 임무를 받아야만 넘는다 — 받지 않는 플레이어에게 장이 0이다. 16장 중 13장이 Lv26 ~ 48(21 ~ 53h)에 몰리고 Lv1 ~ 25는 3장뿐이다(`minLv` 실측). 장 수령은 이미 장 본문을 보여 준다(중복) |
| (b) 경로 게이트 레벨 묶음 | 모든 플레이어가 지나간다. 결정론적(`mapRouteGateLevels`는 `MAPS`만의 함수). 레벨과 단조 | 묶음 경계를 정해야 한다(아래 표). 44 → 48 구간이 길다(지역이 없다) |
| (c) 구역 보스 경계 | "장 보스"라는 말에 맞다 | 구역 보스는 선택이다(게이지 회피 · 여정당 1회). 처치 = 승리 직후라 결산이 승리 뒤 화면이 된다(Wave 127 · D1과 부딪힌다). 구역 보스가 없는 묶음이 있다(Lv1 ~ 5 · 25 · 42 ~ 44) |

**권고: (b).** 장은 지역 묶음이고, 본편 장 완료 · 구역 보스 격파 · 토벌 의뢰는 그 장의 결산에 "큰 순간"으로 들어간다(c와 a의 장점은 결산 내용으로 가져온다). 장 보스 개념(B5)은 보류 범위이므로 장 경계에 보스를 걸지 않는다.

### 1.2 장 표

장 지역 = `type !== 'safe'` · `monsters.length > 0` · `level !== 'infinite'` · 경로 게이트(`getMapRouteGate(...).routeGateLevel`)가 null이 아님. 장 번호 = 게이트가 들어가는 묶음. 묶음 하한은 `CHAPTER_BANDS`(아래)가 소유하고 지역 목록은 도출이다(지역을 손으로 적지 않는다 — 계약이 아래 표를 골든으로 고정).

장이 아닌 곳: 안전지대 6곳(황금 왕국 포함 — 사냥할 수 있어도 안전지대다), 혼돈의 심연(층이 진행을 정한다), 봄의 정원 · 서리 폭풍 유적(계절), 고대 보물고(열쇠). 이곳으로 들어가도 넘음이 없다.

경계 근거: 게이트가 실제로 뛰는 곳(5 → 7, 12 → 14, 18 → 25, 25 → 35, 36 → 40, 40 → 42, 44 → 48)에서 자르고, 1장 · 2장은 초반 정지점을 위해 짧게 둔다(첫 1시간 안에 첫 결산 — 온보딩 "첫 세션의 끝"). 7장(27h)은 지역이 둘뿐이라 더 자를 근거가 없다 — 그 구간의 정지점은 토벌 의뢰 · 본편 장(이미 있다)이 맡는다. 1회차는 보통 1 → 8장, 결산 7번이다.

장 이름은 지역 이름의 전체 문자열을 담지 않는다(길 잃은 여행 · 발견 원칙, 계약).

### 1.3 넘음(crossing) — 결정론적 정의

- 상태 `stats.currentRun.chapters.reached` = 이번 여정에서 들어선 가장 높은 장.
- **넘음** = `move(loc)`가 장 지역 `loc`로 이동하고 `chapterOf(loc) > reached`일 때. 레벨이 올라도, 지역을 지나 걸어도 들어가지 않으면 넘지 않는다(장 = 지금 있는 땅).
- 넘음 한 번에 일어나는 일(같은 payload 안, 순수 함수 `advanceChapterOnEntry(player, loc)`):
  1. 떠나는 장(`reached`)의 결산 `ChapterRecap`을 **그 순간의 값으로 굳혀** `recaps`에 붙인다.
  2. `reached = chapterOf(loc)`, 표식(`mark`)을 지금 값으로 다시 찍는다.
- **지나친 장(접기):** 떠나는 장의 탐험 수가 `BALANCE.CHAPTER_RECAP_MIN_EXPLORES`(1) 미만이면 결산을 만들지 않고, 표식은 그대로 두고 `mark.passed`에 그 장 번호를 더한다. 다음 결산이 "지나친 장: 4장"을 한 줄로 말한다. 지역을 걸어서 통과만 한 장이 빈 결산이 되지 않는다.
- 낮은 장으로 돌아가면 아무 일도 없다(`reached`는 내려가지 않는다). 결산은 "그 장에 들어선 뒤부터 다음 장에 들어설 때까지"의 기간 기록이다 — 그 사이 앞 장 지역에서 한 일도 들어간다(문서화된 의미).

순서: payload 안에서 `startExpedition` **뒤**에 둔다 — 안전지대에서 새 장 지역으로 바로 출발하는 이동(여행자의 쉼터 → 화염의 협곡 등)에서도 새 원정 id를 결산에 붙이기 위해서다.

### 1.4 데이터 모델

```ts
// utils/chapterRecap.ts (판정 · 뷰모델 소유), data/chapters.ts (CHAPTER_BANDS · 이름)
export interface ChapterMark {
    chapter: number;
    level: number;
    job: string;
    counters: Pick<Record<JourneyCounterKey, number>, 'kills' | 'bossKills' | 'explores' | 'relicCount'>;
    signatures: number;          // getDiscoveredSignatureNames(player).length
    storyClaimed: number;        // stats.claimedQuestIds ∩ MAIN_STORY_QUEST_IDS 수
    areaBosses: string[];        // 그 순간 areaBossDefeated의 true 키
    huntRounds: number;          // 완수한 토벌 의뢰 차수 합 — 판정은 utils/huntContracts.ts에 함수로 둔다
    eliteTitles: number;         // titles 중 ELITE_TITLE_PREFIX 수
    passed: number[];            // 접힌 장 번호
}
export interface ChapterRecap {
    chapter: number;             // 떠난 장
    passed: number[];
    expeditionId: string | null; // 넘은 순간의 activeExpedition.id — 원정 정리 시트가 이 값으로 고른다
    levelFrom: number; levelTo: number;
    explores: number; kills: number; bossKills: number; relics: number;
    moments: ChapterMoment[];    // 굳힌 큰 순간(아래), 우선순위 순, 최대 3
}
export type ChapterMoment =
    | { kind: 'areaBoss'; names: string[] } | { kind: 'story'; count: number }
    | { kind: 'job'; job: string } | { kind: 'signature'; count: number }
    | { kind: 'hunt'; count: number } | { kind: 'eliteTitle'; count: number };
// CurrentRunProgress에 선택 필드로 더한다
chapters?: { reached: number; mark: ChapterMark; recaps: ChapterRecap[] };
```

- 범위: 여정(`stats.currentRun` 안). 사망(`handleDefeat`) · 계승(`ASCEND`) · 다시 시작(`RESET_GAME`)이 `createCurrentRunProgress`로 새로 만들 때 `chapters = { reached: 1, mark: 지금 값(Lv1), recaps: [] }`를 함께 찍는다. 그래서 초기화 코드를 따로 쓰지 않는다. `pickPermanentPlayerState`에는 넣지 않는다.
- 큰 순간 우선순위: 구역 보스 격파(표식 이후 새 키, 이름 최대 2 + "외 N") → 이야기 임무 완료 수 → 전직 → 새 전설 각인 수 → 토벌 의뢰 완수 수 → 새 정예 칭호 수. 0인 것은 넣지 않는다. 구역 보스 이름은 격파한 것이라 발견 원칙 안이다. 정예 칭호 · 각인은 수만(Wave 102).
- 크기: 장 ≤ 11 → `recaps` ≤ 10개, 개당 수십 바이트.

### 1.6 화면

- **원정 정리 시트(`ExpeditionDebriefCard`)의 맨 위 칸** `data-testid="debrief-chapter-recap"`. 그 원정 중에 넘은 장이 있을 때만 그린다. 결산이 둘 이상이면 최신이 위, 칸 두 개까지 + "외 N장" 한 줄.
  - 칸 구성: 머리 `MSG.CHAPTER_RECAP_EYEBROW`('장 결산') · 제목 `N장 · 이름` · 수치 칩 줄(레벨 a → b · 탐험 · 처치(보스) · 유물) · 큰 순간 최대 3줄 · 지나친 장 한 줄.
  - 새 단추 없음. 시트의 금빛 주 행동(귀환 추천)이 그대로 하나다. 닫기는 기존 '닫기'.
  - 시트를 닫아도 따로 적는 값이 없다 — 표시는 `expeditionId` 짝으로만 고른다(확인 기록 쓰기 0). 다시 열면 같은 결산이 다시 보인다.
- 토큰: `.ae-card.is-quiet` 칸 · `Chip` · `font-fira tabular-nums` 숫자 · 11px 이상 · 말줄임 없음(Wave 67 · 132 · 133).
- **P1 능력치 탭 '이번 여정의 장'**: `recaps` 전부를 같은 뷰모델로, 여정이 끝나면 비워진다. 원정 밖에서 넘은 결산(`expeditionId: null`)의 유일한 표시처다.
- **P1 `FieldStage` 장 칩** `N장`: 지금 지역의 장 번호(표시 전용 도출, 상태 없음). 길 잃은 여행이면 그리지 않는다(진입 레벨을 숨기는 규칙과 같은 이유).

전투 결과 카드(`PostCombatCard`, 접힌 카드 포함)에는 아무것도 더하지 않는다 — 결산은 승리마다 오는 선택이 아니다(Wave 127 · D1).

### 1.7 MSG 키 (B1)

`CHAPTER_RECAP_EYEBROW` '장 결산' · `CHAPTER_RECAP_TITLE(n, name)` · `CHAPTER_RECAP_ARIA(n)` · `CHAPTER_RECAP_LEVEL(from, to)` '레벨 a → b' · `CHAPTER_RECAP_EXPLORES(n)` '탐험 N번' · `CHAPTER_RECAP_KILLS(n, boss)` '처치 N · 보스 M'(M 0이면 생략) · `CHAPTER_RECAP_RELICS(n)` '유물 N개' · `CHAPTER_RECAP_MOMENTS_HEADING` '큰 순간' · `CHAPTER_RECAP_MOMENT_AREA_BOSS(names, more)` · `CHAPTER_RECAP_MOMENT_STORY(n)` '이야기 임무 N개 완료' · `CHAPTER_RECAP_MOMENT_JOB(job)` (`withJosa(job, '으로/로')` + ' 전직' — "도적으로 전직") · `CHAPTER_RECAP_MOMENT_SIGNATURE(n)` '새 전설 각인 N개' · `CHAPTER_RECAP_MOMENT_HUNT(n)` '토벌 의뢰 N번 완수' · `CHAPTER_RECAP_MOMENT_ELITE_TITLE(n)` '새 정예 칭호 N개'(계승 요약과 같은 말) · `CHAPTER_RECAP_PASSED(labels)` '지나친 장: 4장' · `CHAPTER_RECAP_MORE(n)` '외 N장' · P1 `FIELD_STAGE_CHAPTER_CHIP(n)` · P1 `STATS_CHAPTER_RECAPS_HEADING` '이번 여정의 장'.
장 이름 11개는 `data/chapters.ts`(데이터 — 지역 이름이 `maps.ts`에 있는 것과 같다).

### 1.8 경계 사례

| 상황 | 동작 |
|---|---|
| 장 중간 사망 | 새 여정 = 새 `currentRun` → 1장부터. 아직 원정 정리에서 보지 못한 결산은 여정과 함께 사라진다(사망 화면은 자기 요약이 있다) |
| 계승 | 같다(1장부터). 마지막 장(8장)의 결산은 만들지 않는다 — 계승 화면의 회차 요약(`AscensionCycleSummary`)이 그 자리다 |
| 계승을 미루고 9장 이상 | 같은 규칙. 8장 결산은 9장 지역에 들어설 때 생긴다 |
| 혼돈의 심연 | 장이 아니다 — 들어가도 `reached` 불변, 장 칩 없음 |
| 안전지대 · 계절 · 열쇠 지역 | 장이 아니다 — 넘음 없음 |
| 이전 세이브(`chapters` 없음) | 첫 이동에서 조용히 시작: `reached = max(chapterOf(지금 위치), chapterOf(목적지))`, 표식 = 지금 값, 결산 만들지 않음(기준점 없는 값을 지어내지 않는다 — Wave 100 · 108 원칙) |
| 길 잃은 여행(`isBlindMap`) | 넘음 · 결산은 그대로(지역 이름이 없는 숫자 기록이다). 결산 칸에 지역 이름을 쓰지 않는다. 장 칩만 숨긴다 |
| 걸어서 지나친 장 | §1.3 접기 |
| 한 원정에서 두 장 넘음 | 두 결산 모두 그 원정 id → 시트에 둘 다 |
| 원정 없이 장 지역에 있음(이전 세이브 · 이상 상태) | `expeditionId: null` → 능력치 탭에서만 |
| 보스전 중 사망 vs 일반 사망 | B1과 무관(전투 경로를 건드리지 않는다) |
| 리로드 | 결산은 세이브 봉투 안 `player`에 있다. 원정 정리 시트가 확인되지 않았으면 기존 규칙(`!reviewedAt`)대로 다시 뜬다 |
| 지도 데이터 변경(게이트 이동) | 장 번호가 바뀔 수 있다 — 골든 표 계약이 붉어져 의도적 갱신을 요구한다 |

실패 상태: `chapterOf` 실패(모르는 지역) → null → 넘음 없음. 결산 계산 중 값이 비정상이면 0으로 정규화(`toCount`). 화면은 결산이 없으면 칸을 그리지 않는다.

### 1.9 자연 플레이

이동 payload에 필드 하나를 더할 뿐, 기록 줄 · 난수 · 디스패치 수 · 액션 수가 같다. 드라이버 결과 파일은 `player.stats`를 직렬화하지 않는다(`runs[]` 요약). **기대: 바이트 동일.** 다르면 그것이 결함이다(§4.3).

## 2. B6 돌기둥의 증언

### 2.1 개념과 이름

- 화면 이름 **'돌기둥의 증언'**, 한 줄은 '증언'. 본편 1장 본문의 "오래된 돌기둥"에서 이어진다. '묘비'(공개 묘비 · 회수 묘비) · '기록'(모험 기록 · 기록 탭) · '잔향'(유물의 잔향)과 겹치지 않게 골랐다 — `one-concept-one-name` 계약의 `VARIANTS`에 '죽음의 기록' · '망자의 기록'을 다른 이름으로 더한다.
- 세계 설정(새로 더하는 정사): 쓰러진 자의 에테르는 제국이 땅 곳곳에 세운 돌기둥으로 흘러들어 마을에서 다시 눈을 뜬다. 죽을 때마다 그 자리의 돌기둥이 먼저 쓰러진 이들의 목소리 한 조각을 들려준다. 장을 따라가면 "왜 나는 돌아오는가 — 돌기둥이 봉인석의 에테르를 끌어 쓴다 — 그 근원은 심연과 관문 너머"로 이어진다. 본편 16장(봉인석 · 마왕 · 균열)과 모순되지 않고 그 뒷면을 채운다. 게임 규칙(사망하면 처음부터 · 정수는 남는다)과도 맞다.

### 2.2 구조와 수

| 묶음 | 줄 | 선택 |
|---|---|---|
| 장 1 ~ 8 | 장마다 일반 3 + 강적 1 = 32 | 일반은 순서대로, 강적은 하나 |
| 장 9 ~ 11 | 장마다 일반 2 + 강적 1 = 9 | 〃 |
| 혼돈의 심연 | 3 | 순서대로(적 종류 무관) |
| 장 밖(계절 · 열쇠 · 황금 왕국) | 2 | 순서대로 |
| **합계** | **46** | |

- 묶음 = 사망 순간의 `player.loc`: 장 지역이면 그 장, 혼돈의 심연이면 `abyss`, 그 밖은 `wild`.
- 적 종류 = 쓰러뜨린 적(`state.enemy`)이 `isBoss` · `isElite` · `huntChampion` 중 하나면 `strong`, 아니면 `field`. 1회차 초반 사망의 89%가 정예라(원장 §117) 강적 줄이 먼저 열린다.
- 장마다 수를 다르게 둔 이유: 9 ~ 11장은 계승을 미룬 여정만 간다. 사망 분포(1회차 사망의 다수가 1 ~ 5장)를 보면 46줄이면 몇 회차에 걸쳐 모이고, 쓸 문장 양도 현실적이다.

### 2.3 선택 규칙 (난수 없음)

`selectDeathLore(ledger, group, kind, deathsAfter)`:
1. `kind === 'strong'`이고 그 장의 강적 줄을 아직 듣지 않았으면 → 강적 줄.
2. 아니면 그 묶음의 일반 줄 중 아직 듣지 않은 첫 줄(순서).
3. 일반을 다 들었고 강적 줄이 남았으면 → 강적 줄(일반 사망으로도 결국 열린다).
4. 묶음을 다 들었으면 → 이미 들은 줄 중 `(deathsAfter) % n`번째(계정 사망 수로 도는 결정론적 순환, `isNew: false`). 다른 묶음의 줄을 끌어오지 않는다(장소와 증언의 짝을 지킨다).

`Math.random` · `actionRng` · `deriveSeed`를 쓰지 않는다 — 순서 + 계정 사망 수만으로 정해진다.

### 2.4 데이터 모델 · 쓰기 · 읽기

```ts
// data/deathLore.ts — 줄 정의(데이터, 아래 §2.7 전문). id: 'c{n}-f{i}' · 'c{n}-s' · 'abyss-{i}' · 'wild-{i}'
// utils/deathLore.ts — 묶음 판정 · 선택 · 정규화 · 뷰모델
// PlayerStats에 선택 필드
deathLore?: string[];            // 들은 순서 그대로, 중복 없음, 계정 범위
// RunSummary(buildRunSummary 반환형)에 선택 필드 — 사망 화면 전용, 저장되지 않는다
deathLore?: { id: string; text: string; isNew: boolean; collected: number; total: number };
```

| 종류 | 위치 |
|---|---|
| **쓰기(유일)** | `reducers/handlers/combatHandlers.ts` `settleNonVictory`의 `result.kind === 'defeat'` 갈래: `recordDeathLore(state.player, state.enemy)` → `{ ledger, view }`. `player.stats.deathLore = ledger`, `runSummary = { ...result.runSummary, deathLore: view }`. 두 패배 경로(행동 턴 · 소모품 턴)가 모두 여기로 온다 — 실제 사망 경로는 이 하나다(`GS.DEAD`를 세우는 다른 곳은 QA 시드 API뿐) |
| 넘기기 | `utils/permanentProgress.ts` `pickPermanentPlayerState`가 `kind`와 무관하게 `deathLore`를 복사한다(쓰기가 아니라 운반 — `ruleDeclinePassIds`와 같은 줄) |
| 범위 표 | `journeyScope.ts` 머리 주석의 `account` 목록에 '돌기둥의 증언'. `JourneySurfaceItem`에 `'deathLore'`, `DEATH_SURFACE.kept` · `ASCENSION_SURFACE.kept`에 추가, `MSG.JOURNEY_ITEM_LABELS.deathLore` '돌기둥의 증언'(사망 화면이 그 증언을 보여 주므로 남는 것 목록에도 있어야 한다 — Wave 109) |
| 정규화 | `readDeathLoreLedger(value)`: 문자열 배열 · 알려진 id만 · 순서 유지 · 중복 제거. 없으면 `[]` |
| 읽기 | `RunSummaryCard`(증언 칸) · P1 능력치 탭 '계승 기록' 아래 증언 목록 |

`RESET_GAME`(다시 시작)은 `settleNonVictory`를 거치지 않으므로 증언을 남기지 않는다 — 죽음이 아니다. 부활 수단으로 살아난 전투도 패배가 아니다.

### 2.5 사망 화면

- 위치: `run-summary-killed-by` 바로 아래 `data-testid="run-summary-death-lore"` 칸(`.ae-well`). 머리 줄: '돌기둥의 증언' · 상태 칩('새 증언' 금빛 / '이미 들은 증언' 중립) · 모은 수 `N/46`(`tabular-nums`). 본문: 증언 한 줄(13px, 말줄임 없음, 375px에서 3 ~ 4줄).
- 단추 없음. 주 행동은 기존 '다시 시작' 하나.
- 첫 사망의 마일스톤 이야기 카드(`first_death`)와 함께 보일 수 있다 — 증언 칸이 위, 마일스톤 카드가 아래(서로 다른 말을 한다).
- 계승 · 사망 화면의 "다음 여정에 남는 것" 줄에 '돌기둥의 증언'이 표에서 자동으로 들어간다.
- P1 능력치 탭: 첫 증언을 들은 뒤에만 '돌기둥의 증언 N/46' 묶음이 생긴다(듣기 전에는 존재를 알리지 않는다 — 발견 원칙). 들은 순서로 목록, 듣지 않은 줄의 자리 · 장소 · 조건은 그리지 않는다.

### 2.6 경계 사례 · 실패 상태

| 상황 | 동작 |
|---|---|
| 보스전 사망 | `strong` → 그 장의 강적 줄 우선 |
| 일반 몬스터 사망 | `field` → 다음 일반 줄 |
| 토벌 의뢰 우두머리 · 정예 · 숨은 보스 · 망령(다른 차원의 묘비) | `strong`(정예 · 우두머리 플래그) |
| 혼돈의 심연 사망 | `abyss` 3줄 순서 |
| 계절 · 열쇠 지역 · 황금 왕국 사망 | `wild` 2줄 |
| 묶음을 다 들음 | §2.3-4 순환, '이미 들은 증언' |
| 46줄 모두 들음 | 같은 순환. 모은 수 46/46 |
| 계승 · 다시 시작 | 장부 유지, 새 줄 없음 |
| 이전 세이브(필드 없음) | 빈 장부로 읽는다. 지난 사망은 소급하지 않는다(지어내지 않는다) |
| 사망 세이브를 리로드 | `dead`는 복원되지 않고 `runSummary`도 저장되지 않으므로 그 사망의 증언 화면은 다시 볼 수 없다. 장부에는 이미 들어 있어 능력치 탭(P1)에서 읽는다 |
| 길 잃은 여행 | 그대로 보인다. 증언 문장은 지역 이름을 담지 않는다(계약) — 사망 화면은 이미 쓰러뜨린 적 이름을 보이므로 정보량이 늘지 않는다 |
| 데이터에서 줄을 지움 | 정규화가 모르는 id를 버린다 → 모은 수가 줄 수 있다. 줄 삭제는 금지 규칙(계약: id 집합은 늘기만 한다, 골든) |
| `state.enemy`가 null(이상 상태) | `field`로 판정 |

### 2.7 증언 전문 (46줄)

문체: 짧은 서술 1 ~ 2문장, 플레이어 언어(약어 없음), 지역 · 보스 고유 이름 없음, 보간 없음(조사 판정 불필요). 같은 장 안에서는 순서대로 읽힐 때 이어진다.

**1장 깨어나는 숲**
- c1-f1: 숲의 돌기둥이 희미하게 울렸다. 쓰러진 자의 에테르는 흩어지지 않고 가장 가까운 돌기둥으로 흘러든다.
- c1-f2: 돌기둥에 새겨진 문장은 제국의 것이었다. 누군가 이 땅 곳곳에 돌기둥을 세우고, 쓰러진 이들을 다시 일으키려 했다.
- c1-f3: 돌기둥이 오래된 목소리를 들려주었다. "실험은 성공이다. 이제 우리 병사는 죽어도 마을에서 다시 눈을 뜬다."
- c1-s: 강한 적 앞에서 쓰러지는 순간, 돌기둥은 그 적의 모습까지 새겨 두었다. 돌기둥은 패배를 잊지 않는다.

**2장 물 아래의 길**
- c2-f1: 호수 밑바닥에도 돌기둥이 잠겨 있었다. 물에 잠긴 돌기둥은 마지막으로 쓰러진 병사의 이름을 되뇌고 있었다.
- c2-f2: 광부들은 돌기둥을 되돌림의 돌이라 불렀다. 갱도가 무너져도 돌 곁에서 다시 깨어났기에, 그들은 더 깊이 팠다.
- c2-f3: 수정 속에 갇힌 목소리가 말했다. "돌아올 때마다 무언가를 조금씩 두고 온다. 나는 고향의 이름을 잊었다."
- c2-s: 물 아래에서 쓰러진 자의 에테르는 무겁게 가라앉는다. 돌기둥이 그것을 끌어올리기까지 오래 걸렸다.

**3장 바람과 불씨**
- c3-f1: 무너진 전초의 돌기둥에는 군번이 빼곡했다. 제국은 같은 병사를 몇 번이고 전장에 다시 보냈다.
- c3-f2: 바람이 지난 전쟁의 함성을 실어 왔다. 마법전쟁은 끝났지만 돌기둥에 묶인 병사들의 전쟁은 끝나지 않았다.
- c3-f3: 불꽃 속 돌기둥이 경고했다. "되돌림에는 값이 있다. 돌아오는 것은 어제의 너보다 조금 가벼운 너다."
- c3-s: 옛 지휘관의 마지막 명령이 돌기둥에 남아 있었다. "물러서지 마라. 돌기둥이 너희를 다시 세운다."

**4장 용의 그늘**
- c4-f1: 용들은 돌기둥을 부수지 않았다. 둥지 가장자리의 돌기둥만은 이끼 하나 없이 닦여 있었다.
- c4-f2: 탑의 기록관이 남긴 글. "되돌림의 술식은 용의 숨결에서 왔다. 우리는 그것을 빌렸고, 돌려주지 않았다."
- c4-f3: 돌기둥 아래에 용의 문자가 한 줄 덧새겨져 있었다. "빌린 숨은 언젠가 주인에게 돌아온다."
- c4-s: 용의 불길에 타 버린 에테르도 돌기둥은 끝내 모아 왔다. 다만 돌아온 자의 꿈에는 오래도록 붉은 날개가 나왔다.

**5장 갈라진 대륙**
- c5-f1: 버려진 연구실의 돌기둥은 금이 가 있었다. 그 틈으로 새어 나온 에테르가 망자들을 깨우고 있었다.
- c5-f2: 얼음 아래의 돌기둥은 얼어붙은 채로도 숫자를 세고 있었다. 돌아온 횟수일까, 남은 횟수일까.
- c5-f3: 쇠붙이 도시의 병기들도 쓰러질 때마다 같은 자리에서 다시 움직였다. 제국은 돌기둥의 술식을 쇠에도 새겼다.
- c5-s: 강적이 쓰러진 자에게 속삭였다. "네가 돌아올 때마다 돌기둥은 어딘가에서 에테르를 끌어온다. 어디서일 것 같으냐."

**6장 하늘의 상처**
- c6-f1: 세계수의 뿌리는 모든 돌기둥과 이어져 있었다. 돌기둥이 끌어온 에테르는 본래 세계수의 것이었다.
- c6-f2: 폭풍이 걷힌 자리에서 돌기둥의 목소리가 떨렸다. "봉인석과 돌기둥은 같은 돌에서 깎았다. 하나를 쓰면 다른 하나가 마른다."
- c6-f3: 구름 위 정원의 돌기둥은 하늘 쪽으로 기울어 있었다. 위에서 누군가 끌어당기는 것처럼.
- c6-s: 타락한 수호자는 쓰러진 자를 끝까지 내려다보았다. 그 눈에는 분노보다 오래된 피로가 있었다.

**7장 깊은 어둠**
- c7-f1: 감옥의 돌기둥에는 쇠사슬이 감겨 있었다. 제국은 돌아오고 싶지 않은 자도 돌아오게 만들었다.
- c7-f2: 미궁의 벽에 같은 이름이 수백 번 새겨져 있었다. 한 사람이 같은 자리에서 수백 번 쓰러지고 일어난 흔적이었다.
- c7-f3: 가장 깊은 돌기둥이 처음으로 물었다. "너는 왜 계속 돌아오는가. 제국의 명령은 오래전에 끊겼다."
- c7-s: 어둠 속 강적에게 쓰러질 때 돌기둥의 빛이 잠시 꺼졌다. 돌아오는 길이 처음으로 멀게 느껴졌다.

**8장 왕좌 앞에서**
- c8-f1: 어둠의 성에도 돌기둥이 있었다. 성의 주인은 그것을 부수지 않고, 그 곁에 왕좌를 놓았다.
- c8-f2: 왕좌를 지키던 자가 돌기둥을 쓰다듬었다. "너희 제국은 죽음을 길들였다고 믿었지. 우리는 그 고삐를 쥐었을 뿐이다."
- c8-f3: 돌기둥이 기억하는 마지막 제국 기록. "되돌림의 근원을 봉인하라. 그 열쇠는 돌아오는 자에게 맡긴다."
- c8-s: 이곳에서 쓰러진 에테르는 돌기둥으로 돌아가기 전, 한순간 왕좌 쪽으로 끌려갔다. 무언가가 그것을 삼키려 했다.

**9장 잊힌 성역**
- c9-f1: 강을 따라 흐르는 에테르는 모두 돌기둥이 놓친 것들이었다. 돌아오지 못한 자들이 강이 되었다.
- c9-f2: 신전의 사제들은 돌기둥을 우상이라 불렀다. 그들은 단 한 번의 죽음만을 믿었다.
- c9-s: 깊은 곳의 강적은 돌기둥의 빛을 두려워했다. 쓰러진 자가 사라지는 그 순간에만 다가왔다.

**10장 무너진 서고**
- c10-f1: 금서의 마지막 서가에 돌기둥의 설계도가 있었다. 서명란에는 이름 대신 관문의 문장이 찍혀 있었다.
- c10-f2: 무너진 요새의 돌기둥은 거꾸로 서 있었다. 에테르를 모으지 않고 어딘가로 흘려보내는 돌기둥이었다.
- c10-s: 차원을 찢는 자에게 쓰러지자 돌기둥이 두 곳에서 동시에 울렸다. 돌아올 자리가 하나가 아니었다.

**11장 에테르의 끝**
- c11-f1: 관문 앞의 돌기둥이 최초의 것이었다. 그 표면에는 제국보다 오래된 손자국이 남아 있었다.
- c11-f2: 공허 속에서 돌기둥의 목소리가 거꾸로 들렸다. "돌아오는 것이 아니다. 너는 매번 처음으로 오고 있다."
- c11-s: 마지막 전장의 기사는 쓰러진 자의 에테르를 보며 고개를 숙였다. 그는 한때 가장 많이 돌아온 자였다.

**혼돈의 심연**
- abyss-1: 심연에는 돌기둥이 없다. 그런데도 쓰러진 자는 돌아왔다. 무언가가 아래에서 밀어 올린 것이다.
- abyss-2: 깊이 내려갈수록 돌아오는 길이 짧아졌다. 심연은 돌기둥보다 먼저 있던 되돌림의 근원이었다.
- abyss-3: 바닥의 목소리가 말했다. "제국은 나를 봉인하고 돌로 나누어 가졌다. 너는 내 조각을 따라 돌아온다."

**장 밖**
- wild-1: 돌기둥이 닿지 않는 땅에서 쓰러졌는데도, 에테르는 먼 길을 돌아 마을로 돌아왔다.
- wild-2: 때를 잃은 땅의 공기는 돌기둥의 부름을 흐리게 했다. 돌아오기까지 유난히 긴 꿈을 꾸었다.

## 5. 우선순위 · 위험 · 질문

### 5.1 구현 범위

- **P0:** `data/chapters.ts` · `utils/chapterRecap.ts` · 이동 payload 한 줄 · `CurrentRunProgress.chapters`(생성 · 정규화) · 원정 정리 결산 칸 · `data/deathLore.ts`(46줄) · `utils/deathLore.ts` · `settleNonVictory` 한 줄 · 운반 · 범위 표 · 사망 화면 증언 칸 · MSG · 계약 3종 · e2e 확장 · 자연 플레이 비교.

- 1 PR 권고(P0 + P1). 두 기능이 서로 의존하지 않으므로 갈라도 된다.

### 5.2 위험 (순위)

1. **`normalizeCurrentRunProgress`가 새 필드를 버린다** — 필드별로 다시 만드는 함수라 빠뜨리면 불러올 때마다 장이 1로 돌아가 같은 결산이 반복된다. 계약의 왕복 테스트로 막는다.
2. **`pickPermanentPlayerState`에 운반 줄을 빠뜨린다** — 증언이 첫 사망에 사라진다(`stats`는 초기값에서 다시 짓는다). `journey-surface-copy` 확장으로 막는다.
3. **이동 payload에 기록 줄을 더하고 싶은 유혹** — "N장에 들어섰다" 한 줄이 드라이버 기록 id 카운터 · 필드 무대 발견 카드를 움직인다. 이 명세는 기록 줄 0이다. 장 진입 알림이 필요하면 P1 장 칩(표시 도출)으로 한다.
4. **장 이름 '장'과 본편 16장의 내부 명칭 충돌** — 화면에는 본편이 '[이야기]' 임무로만 보여 지금은 겹치지 않지만, 마일스톤 문구 "다음 권역을 준비하자"(`milestoneStory.ts` `first_area_boss`)가 같은 개념의 두 번째 이름이 된다(질문 Q3).
5. **7장 27시간** — 결산 간격이 가장 긴 구간이 그대로다. 이 명세는 회차 길이를 바꾸지 않으므로 고치지 않는다. 사람 플레이테스트에서 "7장이 지루하다"가 나오면 B3 · B5 쪽 문제다.
6. **새 정사(돌기둥 설정)** — 이후 본편 · 이벤트 문장과 어긋날 수 있다. 설정 요약(§2.1)을 이 문서에 고정해 참조점으로 둔다.
